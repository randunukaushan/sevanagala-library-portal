# Needs, Projects and Asset Management

## 1. Purpose

### 1.1 Objective

Define how the portal represents development needs, groups them into projects, tracks fulfilment, and records physical assets received by the library.

## 2. Core Concepts

### 2.1 Need

A **Need** is a specific requirement that can be measured and supported.

Examples:

- 10 desktop computers;
- 20 study chairs;
- 5 bookshelves;
- 100 current English reference books;
- Wi-Fi access equipment;
- one air-conditioning unit for an approved room.

### 2.2 Project

A **Project** groups related needs around a measurable outcome.

Example:

**Digital Learning Corner**

May include:

- computers;
- networking;
- UPS units;
- desks;
- chairs;
- printer;
- staff training.

### 2.3 Asset

An **Asset** is a durable item that the library has received, accepted, and placed under management.

Examples:

- computer;
- router;
- printer;
- air conditioner;
- shelf;
- projector.

Books should usually remain in the collection module rather than being managed as ordinary fixed assets.

## 3. Need Record

### 3.1 Required Fields

Each need should include:

- unique ID;
- title;
- category;
- description;
- purpose;
- target quantity;
- unit;
- priority;
- status;
- related project;
- visibility;
- last verified date;
- created by;
- approved by where required.

### 3.2 Optional Fields

Optional information:

- estimated unit cost;
- estimated total cost;
- minimum specification;
- preferred specification;
- acceptable alternatives;
- target completion date;
- supporting media;
- staff notes;
- maintenance implications.

### 3.3 Units

Use consistent units such as:

- item;
- book;
- set;
- metre;
- connection;
- workstation;
- service package.

Avoid ambiguous values such as "some computers" or "more chairs".

## 4. Need Priority

### 4.1 Priority Values

Recommended:

- Critical
- High
- Medium
- Low

### 4.2 Priority Meaning

**Critical** should be reserved for issues affecting safety, essential service continuity, or another formally approved urgent condition.

**High** means the item materially limits current library service.

**Medium** means meaningful improvement but not an immediate service blocker.

**Low** means useful enhancement after higher needs are met.

### 4.3 Public Wording

Priority should be explained factually. Avoid emotionally exaggerated fundraising language.

## 5. Need Lifecycle

### 5.1 Draft

Staff are still defining the requirement.

### 5.2 Pending Approval

Waiting for authorised confirmation.

### 5.3 Seeking Support

Approved and publicly available.

### 5.4 Partially Pledged

Part of the target is covered by accepted active pledges.

### 5.5 Fully Pledged

Accepted active pledges plus verified received quantity cover the target.

### 5.6 Partially Received

Some items have arrived.

### 5.7 Fulfilled

Approved target has been received and verified.

### 5.8 Paused

Need should not currently receive new support.

### 5.9 Archived

Need is no longer active but remains part of history.

## 6. Project Record

### 6.1 Required Fields

Each project should include:

- project name;
- summary;
- problem statement;
- objective;
- expected beneficiaries;
- project status;
- start date where known;
- target completion date where known;
- related needs;
- responsible library contact role;
- last verified date.

### 6.2 Optional Fields

May include:

- budget estimate;
- milestones;
- photographs;
- plans;
- technical documents;
- external partners;
- impact indicators.

### 6.3 Project Progress

Progress should be derived from verified milestones rather than arbitrary percentages wherever possible.

Example:

- Needs approved
- Equipment sourced
- Installation started
- Installation complete
- Staff handover complete
- Public service launched

## 7. Asset Acceptance

### 7.1 Acceptance Check

Before an equipment donation becomes an asset, verify:

- item identity;
- quantity;
- working condition;
- compatibility;
- safety;
- accessories;
- documentation;
- warranty if any.

### 7.2 Rejected or Unusable Items

Do not count unusable or rejected items toward fulfilled needs.

Record the outcome internally.

### 7.3 Asset Tag

Where the library maintains asset tags, the system should support:

- asset number;
- serial number;
- make/model;
- acquisition source;
- received date;
- condition;
- location;
- custodian;
- warranty details.

## 8. Equipment Planning

### 8.1 Computers

Before publishing a computer need, define:

- intended use;
- minimum RAM;
- storage;
- operating-system approach;
- monitor requirement;
- network capability;
- warranty expectations;
- power requirements.

Exact specifications should be approved at implementation time to avoid publishing obsolete requirements.

### 8.2 Wi-Fi

A Wi-Fi project should consider:

- internet connection;
- router/firewall;
- access points;
- coverage;
- user network separation;
- acceptable-use policy;
- content/security policy where legally required;
- privacy;
- maintenance cost.

### 8.3 Air Conditioning

Before seeking AC equipment, verify:

- room dimensions;
- electrical capacity;
- installation approval;
- energy cost;
- maintenance responsibility;
- ventilation needs.

### 8.4 Furniture

Define:

- quantity;
- dimensions where required;
- intended users;
- durability;
- accessibility needs;
- safe placement.

## 9. Smart Library Roadmap

### 9.1 Collection Renewal

Focus on:

- high-demand books;
- current reference resources;
- outdated-book review;
- English resources;
- children's resources;
- O/L and A/L resources;
- technology and future-skills resources.

### 9.2 Digital Access

Possible needs:

- computers;
- public Wi-Fi;
- printer/scanner;
- charging access;
- digital resource links;
- basic digital literacy.

### 9.3 Digital Catalogue

Later phases may add:

- searchable catalogue;
- new arrivals;
- subject filters;
- language filters;
- availability status where reliable.

### 9.4 Community Learning

Future project types:

- coding basics;
- digital literacy;
- career information;
- reading programmes;
- research skills;
- media and information literacy.

## 10. Data Quality Rules

### 10.1 Verification Date

Active needs should have a last-verified date.

### 10.2 Stale Needs

Needs not reviewed within an approved period should be flagged for review rather than silently remaining current forever.

### 10.3 Quantities

Changes to target, pledged, received, or verified quantities must be auditable.

### 10.4 Estimates

Estimated cost must be labelled as an estimate and must not be presented as a quotation unless supported by an approved quotation.

## 11. Public Reporting

### 11.1 Need Card

Recommended card information:

- title;
- category;
- target;
- pledged;
- verified received;
- remaining;
- status;
- last verified.

### 11.2 Project Card

Recommended:

- title;
- one-sentence outcome;
- status;
- related needs;
- latest update.

### 11.3 Completed Work

Completed projects should remain visible to demonstrate impact and avoid repeatedly seeking support for already fulfilled needs.

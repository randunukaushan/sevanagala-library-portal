# Donor Evidence and Support Pack Framework

## 1. Purpose

### 1.1 Objective

Define the standard English-language evidence pack that will be used when approaching suitable international donors, foundations, CSR programmes, technology partners, book-donation organisations, and community associations.

The final donor pack must be based on verified library data, not estimates or unsupported claims.

### 1.2 Current Status

This is a **template and evidence framework**.

It is not yet an external donor proposal. Final figures, photographs, official contacts, branding, and project requests must be verified and approved before distribution.

## 2. Evidence Flow

### 2.1 Internal Data to External Evidence

The project will use this sequence:

1. staff information forms;
2. 6-8 week visitor usage and demand study;
3. building and facility assessment;
4. collection audit and gap analysis;
5. verified staff priorities;
6. data cleaning and verification;
7. English donor evidence pack;
8. donor-specific proposal or application.

### 2.2 Raw Data

Raw survey sheets and internal records should normally remain internal.

External donor documents should use:

- verified aggregate statistics;
- approved photographs;
- approved quotes or anonymised feedback;
- clear methodology;
- verified quantities and project scopes.

Do not publish unnecessary personal data.

## 3. Standard Donor Pack Structure

### 3.1 Cover

Include:

- approved library name;
- project title: **Sevanagala Smart Library Transformation**;
- approved photograph;
- location;
- date/version;
- official/approved contact;
- statement that the pack contains verified project information.

### 3.2 Executive Summary

Summarise:

- who the library serves;
- the main current challenges;
- evidence gathered;
- the transformation vision;
- the most urgent priorities;
- the type of support being sought.

Keep this section short enough to read in one minute.

### 3.3 Library Profile

Include verified:

- official name;
- responsible authority;
- location;
- opening hours;
- current services;
- staff;
- visitor base;
- current facilities;
- community role.

### 3.4 Current-State Evidence

Present a concise baseline using verified results from:

- visitor counts;
- age-group patterns;
- peak usage times;
- borrowing/reading categories;
- missing-book requests;
- visitor feedback;
- collection audit;
- building/facility survey;
- ICT and connectivity assessment.

### 3.5 User Demand and Community Need

Show:

- total study period;
- number of visits observed;
- age-group distribution;
- most-used collection categories;
- most-requested missing titles/topics;
- main reasons for library use;
- comfort/facility ratings;
- repeated visitor suggestions.

Use charts where they improve understanding.

### 3.6 Collection Condition and Renewal Need

Include verified:

- register total;
- physical inventory total;
- active usable collection;
- repair queue;
- update/replace queue;
- withdrawal-review queue;
- language distribution;
- subject gaps;
- high-priority acquisition categories.

Avoid describing books as simply "useless." Use neutral collection-management terms.

### 3.7 Building and Facility Baseline

Include:

- room/floor measurements;
- heat and ventilation findings;
- lighting;
- electrical readiness;
- shelving/furniture condition;
- toilets/water;
- accessibility barriers;
- safety concerns;
- internet/ICT status.

### 3.8 Transformation Vision

Explain the target progression:

- Stage A — Safe and Functional Library;
- Stage B — Modern Public Library;
- Stage C — Smart and Digital Library;
- Stage D — Community Knowledge and Learning Hub.

Explain that technology is introduced after safety, comfort, infrastructure, and maintenance readiness.

### 3.9 Priority Projects

Each donor-facing project should have:

- project name;
- problem;
- evidence;
- target outcome;
- quantity/scope;
- estimated budget where approved;
- implementation owner;
- maintenance plan;
- measurable success indicators;
- support already pledged/received;
- remaining need.

### 3.10 Suggested Project Packages

Possible packages after verification:

- high-priority book renewal;
- children's reading resources;
- O/L and A/L learning resources;
- English and language-learning resources;
- science/technology/ICT collection renewal;
- furniture and study-space improvement;
- shelving rehabilitation;
- heat/ventilation improvement;
- electrical safety upgrade;
- Wi-Fi/network upgrade;
- digital learning corner;
- printer/scanner and learning equipment;
- accessibility improvements;
- community learning programme.

### 3.11 Governance and Transparency

Explain:

- institutional approval;
- authorised project roles;
- separation of pledge, received, and verified support;
- supporter recognition only with consent;
- no personal bank-account collection;
- official receipt/accounting process where applicable;
- project progress reporting;
- asset/inventory tracking;
- website transparency updates.

### 3.12 Monitoring and Reporting

After support, report:

- quantity received;
- verification date;
- deployment/cataloguing status;
- approved photographs;
- short impact update;
- relevant usage indicators;
- remaining project need.

## 5. Evidence Quality Rules

### 5.1 Verification

A donor-facing figure must have:

- a source;
- a collection date or study period;
- a responsible verifier;
- a clear definition.

### 5.2 Estimates

If an estimate must be used, label it clearly as an estimate and explain the basis.

Do not mix an estimate with a verified figure as if they have equal certainty.

### 5.3 Photographs

Use only approved photographs.

Avoid identifiable children or other people where permission is not available.

### 5.4 Quotes and Feedback

Prefer anonymised themes and aggregate results.

If a direct quote is used, obtain appropriate permission and avoid unnecessary identifying details.

## 6. Donor-Specific Versions

### 6.1 Book Donors

Emphasise:

- collection audit;
- exact missing titles/categories;
- age and education level;
- language;
- quantity;
- acceptable alternatives;
- cataloguing/deployment plan.

### 6.2 Technology Partners

Emphasise:

- user demand;
- electrical readiness;
- internet plan;
- intended use;
- device specifications;
- maintenance;
- staff responsibility;
- replacement lifecycle.

### 6.3 Infrastructure or CSR Partners

Emphasise:

- building/facility baseline;
- heat, furniture, accessibility, electrical, or space problem;
- measured quantities;
- implementation plan;
- maintenance and ownership;
- before/after indicators.

### 6.4 Foundations and Grant Makers

Emphasise:

- community need;
- evidence methodology;
- target outcomes;
- inclusion;
- sustainability;
- governance;
- measurable impact.

## 7. Recommended Final Formats

### 7.1 Core Pack

Prepare:

- a concise English PDF donor pack;
- a one-page summary;
- detailed verified needs table;
- approved photo appendix where useful;
- official request/cover letter.

### 7.2 Website

The public website should support the donor pack by showing:

- approved library profile;
- verified needs;
- project progress;
- last-verified dates;
- approved supporter recognition;
- public contact route.

## 8. Final Release Gate

### 8.1 Before External Distribution

Confirm:

- written project/website approval;
- approved library name and authority;
- approved official contact;
- approved photographs;
- verified study results;
- verified collection/facility figures;
- approved project priorities;
- approved donation/support process;
- approved donor-recognition policy;
- no private or unnecessary personal data;
- correct version/date.

## 10. Working Principle

### 10.1 Evidence Before Request

The final donor story should follow this sequence:

**Current condition -> verified community need -> proposed intervention -> measurable target -> responsible implementation -> transparent progress -> documented impact.**

This allows donors to understand not only what is being requested, but why it is needed, how the request was verified, and how the result will be measured.
